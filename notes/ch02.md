# Chapter 2 - Cargo

## In my own words

This is the path `todo!` is under. The crate is `core` and the macro is `mod.rs`.

`/Users/joelhimanen/.rustup/toolchains/stable-aarch64-apple-darwin/lib/rustlib/src/rust/library/core/src/macros/mod.rs`

On the other hand, `println!` is found under

`/Users/joelhimanen/.rustup/toolchains/stable-aarch64-apple-darwin/lib/rustlib/src/rust/library/std/src/macros.rs`,

the `std`crate.

Both of these crates contain actual Rust code, which is the source that was copied locally when installing `rust-src`. That's why `rust-analyzer` can read it and I can hop into it with `gd`.

`core` is reserved for stuff that doesn't need anything else to run. In contrast, `std` includes stuff that needs e.g. an OS to run (`println!` prints to `stdout`).
Both are in scope because the compiler `rustc` quietly inserts std ans its prelude at the start of every `.rs` file. Also, `std` re-exports core, so everything in core is usable through `std`.

The `dev` profile is unoptimized by default for two main reasons:
- speeding up the edit-compile-test loop (optimising becomes slow in large projetcs)
- debuggability (at `opt-level = 0`, variables get their own slot in memory, etc.)
